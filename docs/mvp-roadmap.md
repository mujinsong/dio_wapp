# MVP 路线

## 已完成

- 微信登录、JWT 登录态和生产配置校验
- 单事务所、多团体业务作用域
- 普通用户、工作人员、团队负责人和管理员角色
- 管理员维护团队成员、负责人角色和启停状态
- 用户身份二维码与工作人员扫码授予积分
- 后端按购券单价和数量计算积分并生成唯一销售单
- 工作人员每日额度、大额积分负责人或管理员审批
- 已入账积分的冲正申请、跨人审批和反向审计流水
- 用户分页查看积分流水
- 管理员按会员编号查询并纠正积分
- 商品管理、定时上架、库存和限购
- 工作人员商品申请、负责人和管理员审批
- 团队负责人直接维护本团队商品
- 商品兑换、订单二维码和工作人员核销
- 待核销订单取消、积分退款和库存恢复
- 未核销订单到期自动退款和库存恢复
- 积分与兑换订单游标分页
- 超时重试复用请求号，防止重复扣款、加分和创建商品
- 服务层与数据库双层余额、价格、库存和限购上限保护
- 身份二维码有效期倒计时与过期失效提示
- 登录及认证接口限频
- MySQL 就绪检查和生产容器模板

## 积分流水

积分属于唯一事务所，多个团体共用同一用户余额。当前流水类型：

```text
staff_add
exchange_cost
order_refund
admin_adjust
```

每次积分变化记录用户、事务所、团体（事务所级纠错为 `0`）、变动前余额、变动值、变动后余额、操作人、关联记录、备注和时间。用户可以查看自己的流水；管理员纠错必须填写原因。

积分主要来自线下购券，不开放用户自由转赠。自由转赠会破坏积分来源追踪，并增加倒卖和洗积分风险。

## 外部上线项

以下工作依赖生产账号或基础设施，不能只靠仓库代码完成：

1. 准备 HTTPS API 域名和反向代理证书。
2. 在微信公众平台配置 request 合法域名。
3. 创建生产 MySQL、Redis 并保存独立密钥。
4. 选择对象存储并配置商品图片上传。
5. 申请微信订阅消息模板，用于审批和核销通知。
6. 完成微信开发者工具真机测试、体验版和审核发布。
